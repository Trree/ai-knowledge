### 宏观架构

[[deepresearch]]设计

整个循环可以拆成 **3 层嵌套 loop**：

```
外层 Loop：遍历研究计划中的每个子问题
  中层 Loop：对单个子问题进行多轮搜索直到信息充分
    内层 Loop：对单次搜索结果中的多个网页逐一阅读评估
```

---

### 外层 Loop：子问题调度

```
研究计划 = [子问题1, 子问题2, ..., 子问题N]
已收集知识库 = {}

for 子问题 in 研究计划:
    result = 中层Loop(子问题, 已收集知识库)
    已收集知识库.merge(result)
    
    // 关键：动态计划修正
    if result 中发现了计划外的重要线索:
        研究计划.append(新的子问题)
    if 某个后续子问题已被当前结果覆盖:
        研究计划.skip(该子问题)
```

**核心机制——动态计划修正**：

比如研究"mRNA 疫苗技术"，原计划没有"脂质纳米颗粒递送"这个子问题，但在阅读某篇文章时发现这是关键瓶颈，就会**动态插入**一个新子问题。

反过来，如果子问题 3 的答案在研究子问题 1 时已经顺带获得了，就**跳过**。

---

### 中层 Loop：单个子问题的搜索策略

这是最核心的部分。对每个子问题执行一个**自主决策循环**：

```
def 中层Loop(子问题, 已有知识):

    搜索轮次 = 0
    该问题的信息池 = []
    
    while True:
        搜索轮次 += 1
        
        // ① Query 构造
        if 搜索轮次 == 1:
            query = 从子问题直接生成搜索词
        else:
            query = 基于(子问题 + 已有结果的缺口)生成 follow-up 搜索词
        
        // ② 执行搜索
        搜索结果 = Google_Search(query)
        
        // ③ 网页阅读（内层 Loop）
        新信息 = 内层Loop(搜索结果, 子问题)
        该问题的信息池.append(新信息)
        
        // ④ 充分性判断（关键决策点）
        判断 = 评估信息充分性(子问题, 该问题的信息池)
        
        if 判断 == "充分":
            break
        elif 判断 == "部分缺失":
            // 生成针对性的补充 query，继续循环
            continue
        elif 判断 == "方向错误":
            // 换一个完全不同的搜索角度
            重置搜索策略()
            continue
        elif 搜索轮次 > 上限:
            // 避免无限循环，标记为"尽力而为"
            break
    
    return 该问题的信息池
```

#### ① Query 构造策略

不是简单地把子问题复制粘贴成搜索词，而是有**多种 query 生成策略**：

```
子问题："锂电池在极寒环境下的性能衰减"

第1轮（直接搜索）：
  → "lithium battery performance cold weather degradation"

第2轮（发现缺具体数据）：
  → "lithium ion battery capacity loss -20°C percentage study"

第3轮（需要对比视角）：
  → "LFP vs NMC battery cold weather performance comparison"

第4轮（追踪到一个关键实验室）：
  → "Idaho National Laboratory battery cold testing results 2024"
```

策略类型：

|策略|触发条件|示例|
|---|---|---|
|**直接搜索**|首轮|子问题原文转 query|
|**精确化**|结果太泛|增加限定词、年份、具体指标|
|**换角度**|当前角度饱和|从学术→产业，从中文→英文|
|**追源头**|发现关键引用|搜索原始论文/机构/数据集|
|**对比验证**|信息冲突|搜索"X vs Y"或第三方评测|
|**反向搜索**|需要反面证据|搜索"X 缺点/批评/争议"|

#### ④ 充分性判断（最关键的决策）

这是区分 Deep Research 和普通搜索的**核心智能**。模型需要判断：

```
已有信息是否足以回答这个子问题？

评估维度：
┌──────────────────────────────────────────┐
│ 1. 覆盖度：关键方面是否都有涉及？          │
│    → "成本对比只找到了购置价，缺运营成本"   │
│                                          │
│ 2. 可信度：来源是否足够权威？               │
│    → "只有博客说法，缺学术/官方数据"        │
│                                          │
│ 3. 一致性：多个来源是否相互印证？            │
│    → "两个来源数据矛盾，需要第三方验证"     │
│                                          │
│ 4. 时效性：信息是否足够新？                 │
│    → "最新数据是2022年的，需要更新"         │
│                                          │
│ 5. 深度：是否有足够的细节支撑论述？          │
│    → "有结论但缺原因解释"                   │
└──────────────────────────────────────────┘
```

判断结果映射到行动：

```
所有维度通过 ──────────→ 标记完成，进入下一子问题
覆盖度不足 ────────────→ 生成补充 query（针对缺失方面）
可信度不足 ────────────→ 搜索更权威来源（论文、官方报告）
一致性冲突 ────────────→ 搜索第三方/meta-analysis 验证
时效性不足 ────────────→ 加上年份限定重新搜索
深度不足 ──────────────→ 搜索 "why" / "mechanism" / "详解"
```

### 内层 Loop：网页阅读与信息提取

```
def 内层Loop(搜索结果, 子问题):
    
    提取的信息 = []
    
    for 网页 in 搜索结果.top_results:
        
        // ① 预筛选（不是每个都读）
        if 网页.snippet 明显不相关:
            skip
        if 网页.域名 已知低质（内容农场等）:
            skip
        
        // ② 读取网页内容
        页面内容 = fetch_and_parse(网页.url)
        
        // ③ 定向提取（不是读全文）
        相关段落 = 从页面内容中提取与子问题相关的部分
        
        // ④ 信息评估
        评估 = {
            "事实性": 是否包含可验证的事实/数据,
            "来源质量": 域名权威性 + 作者专业性,
            "新增价值": 相对于已有信息是否提供了增量,
            "引用价值": 是否值得在最终报告中引用
        }
        
        if 评估.新增价值 > 阈值:
            提取的信息.append({
                "内容摘要": 相关段落的压缩版,
                "原始URL": 网页.url,
                "可信度评分": 评估.来源质量,
                "关键数据点": 提取的具体数字/结论
            })
    
    return 提取的信息
```

**关键点——不是"读完所有网页"，而是"选择性阅读+定向提取"**。长上下文窗口（1M tokens）让它可以在内存中保持大量已读内容，但它仍然会做筛选以提高效率。

### 跨子问题的知识传递

这是三层 loop 之间最精妙的连接：

```
研究子问题1："电动车购置成本"
  → 收集到：特斯拉降价信息、比亚迪价格区间、补贴政策

研究子问题2："电动车日常使用成本" 
  → 搜索时，模型已经知道子问题1中涉及的具体车型
  → 自动将 query 锚定在相同车型上，保证报告的一致性
  → 如果子问题1中某篇文章顺带提了使用成本，直接复用，不重复搜索

研究子问题3："残值与贬值"
  → 发现特斯拉频繁降价严重影响残值
  → 回溯标注：这与子问题1的"降价"信息形成因果链
  → 最终报告中会将这两点关联呈现
```

### 异常处理与保护机制

```
// 防止无限循环
MAX_SEARCHES_PER_SUBTOPIC = ~10
MAX_TOTAL_SEARCHES = ~100
MAX_TOTAL_TIME = ~10 minutes

// 防止信息冲突僵局
if 同一问题搜索 > 5次仍有矛盾:
    标记为"存在争议"，在报告中呈现多方观点
    而非继续搜索试图找到"正确答案"

// 防止深度陷阱（rabbit hole）
if 某个子问题消耗了 > 30% 的总搜索预算:
    强制结束，标记为"已尽力覆盖"
    将剩余预算留给其他子问题

// 搜索失败处理
if 某个 query 返回结果极少:
    尝试放宽搜索词
    尝试英文搜索（如果原来是中文）
    仍无结果 → 在报告中标注"公开信息有限"
```

```
              │     │ 执行搜索  │────→ 换 query ─────┤
              │     └────┬─────┘                    │
              │          │                          │
              │          ▼                          │
              │     ┌──────────┐     低质量          │

              │     └────┬─────┘             │      │
              │          │有价值              │      │

              │     └────┬─────┘                    │

              │     ┌────┴────┐                     │
              │     ▼         ▼                     │

                  └──────────┘
```

**一句话总结**：整个 Agentic 循环的灵魂在于**充分性判断**——它不是"搜一次就完事"，而是每搜一次都反问自己"够了吗？还缺什么？"，这个自我评估能力是靠 LLM 的推理（CoT）实现的。
