## 1. 素材清单

### `topic / event / person`

- 2026-04-04，Andrej [[Karpathy]] 发布 gist `llm-wiki.md`，定义 `LLM Wiki` 模式：让 LLM 维护一个持久化、互相链接的 markdown wiki，而不是每次问答临时从原始文档里检索重拼。
- 核心三层结构：`raw sources`、`wiki`、`schema`。
- 核心三类操作：`ingest`、`query`、`lint`。

### `user voice`

- HN 用户质疑：这种模式会不会把原始信息不断重写成更差的二阶信息，长期产生 drift。
- HN 用户质疑：大规模时 scoping / retrieval 不应再靠 LLM 在上下文里猜，应该增加 graph / deterministic retrieval。
- HN 用户反馈：如果把 source 拆细到 chapter 级，输出质量会明显提升，说明用户真正买单的不是概念，而是落地细节。

### `competitor / substitute`

- `NotebookLM`、`ChatGPT file uploads`、经典 `RAG`。
- 人工维护的 `Obsidian / Zettelkasten / wiki`。
- 结构化 memory / MCP / sqlite-vec 一类“persistent memory RAG”方案。

### `adjacent tools / old workflow`

- 旧工作流：资料丢进聊天框，回答用完即弃，知识不沉淀。
- 相邻工作流：Obsidian 人工写卡片，维护成本高，长期容易断更。
- 新工作流：Obsidian 看结果，LLM 负责写 wiki，`AGENTS.md` 或 `CLAUDE.md` 约束 schema 和流程。

### `transaction signal`

- Karpathy gist 页面在 2026-04-22 仍显示 `5,000+ stars` 与 `4,900 forks`，说明这是强分发信号，不是小圈层实验。
- GitHub `llm-wiki` topic 页面已出现 `75` 个 public repos，说明“实现层创业/复刻”已经开始。
- 已出现 `llm-wiki.app` 这类 waitlist 产品，以及 `llm-wiki.net` 这类插件/命令式产品，说明已有团队抢占叙事和获客入口。
- 中文侧已出现聚合站介绍、教程视频和“保姆级搭建教程”，说明中文传播已经起量。

### `counterexample`

- HN 与 gist 评论集中指出：`source must remain source`，不能把 LLM 生成页误当原始真相。
- 评论区多次提到：规模一大，单靠 index + markdown 扫描会失效，需要 graph、hybrid retrieval、schema discipline。
- 也有人指出：这套东西“更适合玩和看 demo，不一定能进入日常工作流”，说明 adoption 不是自然而然发生的。

## 2. 热点表层摘要

- `事件`
  Karpathy 在 2026-04-04 公开了一个 idea file，主张让 LLM 把原始资料编译成持续维护的 wiki，而不是每次问答都临时做检索和拼接。
- `谁在关注`
  AI 工具开发者、agent 玩家、Obsidian 用户、知识管理人群、内容创作者、研究者。
- `市场上一层解读`
  “RAG 过时了”“知识库会自运行”“LLM 不只是回答问题，而是维护知识资产”。

## 3. 差异与突破扫描

- `最接近的 2-3 个对比对象`
  `NotebookLM`、经典 `RAG`、人工 Obsidian / wiki。
- `和它们相比，哪里真的不同`
  真差异不在“能回答问题”，而在“把回答、关系、矛盾、索引都写回成一个长期存在的中间层”。
- `突破点落在哪个维度`
  `编辑一致性`、`知识累积`、`维护成本`、`控制力`。
- `哪些点只是更好，不是更换工作流`
  更强总结、更长上下文、更快检索，这些都只是增量改进，不足以单独构成换工作流。
- `谁会因为这个差异改变行为`
  不是普通聊天用户，而是已经有“长期积累资料”痛点的人：研究型创作者、独立开发者、行业研究者、投资/咨询类个人工作室、小团队项目 owner。

## 4. 二层洞察

- `洞察 1`
  这个热点真正改变的不是“问答质量”，而是知识资产的形成方式。原来 AI 是一次性消费；现在它开始产出一个可复用、可编辑、可版本化的中间层。
- `洞察 2`
  市场最稀缺的不是“再做一个知识库”，而是“把 drift、traceability、schema discipline 做成默认配置”。也就是说，真正能卖的不是梦幻 second brain，而是“更不容易烂掉的 first working system”。
- `洞察 3`
  热度会迅速催生大量通用实现，但第一波真正能成交的往往不是平台，而是针对具体人群的“首包服务”：把他们现有的资料、笔记、会议纪要、研究材料编成可用 wiki。
- `洞察 4`
  这件事最容易复利的部分不是代码，而是模板：`schema`、目录结构、ingest 规则、lint 规则、演示案例、行业化页面模板、验证脚本。

## 5. 可迁移思想

- `底层变化`
  LLM 正从“生成器”转向“维护器”。真正有价值的是让模型持续维护一个外部工件，而不是每次在聊天窗口里重新表演。
- `可复用机制`
  `raw immutable + compiled layer + schema rules + periodic lint`。
- `相邻可迁移场景`
  选题研究、会议纪要、竞品情报、项目决策记录、课程学习、行业跟踪、投研资料、销售案例库。

## 8. 圆桌角色配置

- `圆桌议题`
  围绕 `LLM Wiki` 热度，最值得先卖的是 `首包服务`、`中文模板`，还是 `团队试点 / 治理工具`？
- `参会角色`
  `买方：研究型创作者`
  `买方：小团队项目 owner`
  `卖方：一人咨询/工具卖家`
  `反对者：RAG/知识图谱工程师`
  `交付负责人：实际做首单的人`
- `每个角色的核心立场`
  研究型创作者要的是立刻可用，不想自己搭。
  小团队 owner 要的是减少知识丢失，但不想上重平台。
  一人卖家要的是 7 天内能收钱，交付别太重。
  工程师警惕 drift、traceability、规模扩展。
  交付负责人要求边界清晰、首单可控。
- `为什么这个角色必须在场`
  因为这个热点最容易被“工程兴奋”带偏，必须让买方和交付约束把讨论拉回现实。
- `本轮最深裂缝`
  用户真正买的是“可持续的知识资产”，还是“第一次把杂乱资料整理成能工作的东西”？
- `最意外的反对意见`
  最大风险不是没有需求，而是用户会说“我觉得酷，但我还是不会日常使用”。
- `被直接淘汰的方向`
  `白标 SaaS`
- `被意外抬升的方向`
  `反漂移 Lint/Trace` 被抬升为所有方向的加分件，而不是独立第一产品。
- `自动进入的下一阶段`
  用 3 轮迭代验证：先看清痛点，再看成交信号，再看反例后还能不能成立。

  付费理由偏弱，容易被免费教程替代。

#### 方向 3：AI 工具测评 / 选题资料编译订阅

- `目标人群`
  AI 内容创作者、从业者。
- `一句话价值`
  不是给你新闻，而是给你一套持续累积的专题研究底稿。
- `产品形式`
  订阅。
- `建议价格带`
  `199-599 RMB / 月`
- `优先渠道`
  公众号、知识星球、社群。
- `本轮最大短板`
  持续交付压力存在，容易变成人工 newsletter。

#### 方向 4：团队项目记忆编译 Pilot

- `目标人群`
  小团队产品/技术负责人。
- `一句话价值`
  把会议、PRD、决策记录编成项目记忆层，减少“为什么这么做”失忆。
- `产品形式`
  服务。
- `建议价格带`
  `2999-9999 RMB`
- `优先渠道`
  熟人 B2B。
- `本轮最大短板`
  首单定制性偏高。

#### 方向 5：投资 / 尽调 Wiki 服务

- `目标人群`
  小基金、个人投资者、行业研究者。
- `一句话价值`
  把公司资料与行业材料编成一个可追问、可复盘的尽调 wiki。
- `产品形式`
  服务。
- `建议价格带`
  `1999-7999 RMB`
- `优先渠道`
  投研社群、熟人转介绍。
- `本轮最大短板`
  交付标准容易被用户拉重。

#### 方向 6：反漂移 Lint/Trace 插件

- `目标人群`
  高要求 agent 用户、小团队。
- `一句话价值`
  给 LLM Wiki 加上 source trace、lint、健康检查，降低二阶失真。
- `产品形式`
  工具。
- `建议价格带`
  `299-1999 RMB`
- `优先渠道`
  GitHub、插件市场。
- `本轮最大短板`
  解释成本高，不如“先帮你搭一个”直观。

#### 第 1 轮总结

- `本轮新增信息`
  拿到 HN 与 gist 评论，确认主痛点并不只是“不会搭”，而是“怕 drift、怕规模化、怕用两周就废”。
- `本轮结论`
  先卖能见成果的服务，比先卖抽象工具更稳。
- `排名变化`
  `Topic Wiki 首包` 上升到第 1；`Starter Kit` 暂列第 2；`团队 Pilot` 与 `尽调服务` 居中；`反漂移插件` 作为增强件保留。
- `关键修复`
  讨论从“idea 很酷”转成“买方愿意先为什么付钱”。
- `保留还是淘汰`
  6 个保留。
- `下一轮重点`
  找 transaction signal，分辨“会传播”与“会付钱”。
- `是否收敛`
  否。

### 第 2 轮

相对第 1 轮，做了两处修改：

- 把所有方向都加上“是否能靠模板复利”这一问。
- 把所有方向都按“先卖结果还是先卖工具”重新排序。

#### 变化后的判断

- `窄场景 Topic Wiki 首包`
  从一般服务，压缩为 `固定边界首包`：最多 30 份 source、1 个主题、1 个 vault、1 次 handoff。
- `中文 Starter Kit + 模板库`
  从主产品降成 `转化后端产品`：更适合给已经看过案例、想自己做的人。
- `AI 工具测评 / 选题资料编译订阅`
  从“媒体产品”改成“面向创作者的研究底稿订阅”，更聚焦。
- `团队项目记忆编译 Pilot`
  保留，但限定只做 `单项目试点`。
- `投资 / 尽调 Wiki 服务`
  保留，但只在有熟人渠道时做。
- `反漂移 Lint/Trace 插件`
  从独立产品改成所有交付的默认附加件。

#### 第 2 轮总结

- `本轮新增信息`
  出现了 `llm-wiki.app` waitlist、`llm-wiki.net` 命令式产品、`75` 个 GitHub repos。
- `本轮结论`
  市场已经开始抢“通用产品入口”，但公开付费证据仍偏弱，说明先做通用 SaaS 会落入红海；服务+模板更现实。
- `排名变化`
  `Topic Wiki 首包` 稳居第 1；`Starter Kit` 降为第 3；`选题资料编译订阅` 升到第 2。
- `关键修复`
  把“有热度”与“有成交”分开了。
- `保留还是淘汰`
  保留 5 个，`反漂移插件` 退出主赛道，转为增强模块。
- `下一轮重点`
  用 counterexample 决定最终应卖“首包服务”还是“模板包”。
- `是否收敛`
  否。

### 第 3 轮

进一步压缩为最小可卖单元：

#### 方向 A：窄场景 Topic Wiki 首包

- `最小交付`
  1 个主题 wiki、1 套 schema、1 套目录结构、1 次 ingest、1 份查询演示页、1 份 lint/风险说明。
- `最小定价`
  `999 RMB`
- `最快验证方式`
  用 1 个公开主题做 before/after demo，再卖“按你的资料重做一次”。
- `可沉淀资产`
  schema 模板、行业模板、演示样例、销售文案、FAQ。

#### 方向 B：选题/资料编译订阅

- `最小交付`
  每周 1 个专题 wiki 包，外加 3 个可直接写作/汇报的问题答案。
- `最小定价`
  `199 RMB / 月`
- `最快验证方式`
  做 1 期试刊招募首批用户。
- `可沉淀资产`
  专题数据库、栏目节奏、选题标准。

#### 方向 C：中文 Starter Kit + 模板库

- `最小交付`
  3 套 schema、1 个 vault 模板、1 个 setup 视频、1 个常见错误清单。
- `最小定价`
  `99 RMB`
- `最快验证方式`
  在买过首包的用户中 upsell。
- `可沉淀资产`
  模板库、教程库、安装脚本。

#### 第 3 轮总结

- `本轮新增信息`
  counterexample 基本集中在 `drift / source trace / scale`，这反而说明买家更愿意先买一个“边界清楚、能看见 raw 与 wiki 对照”的首包，而不是先买一个抽象大平台。
- `本轮结论`
  主推方向收敛为：`Topic Wiki 首包`。它把热点的最大吸引力和最大焦虑同时打包卖掉了。
- `排名变化`
  `Topic Wiki 首包` 第 1，`选题/资料编译订阅` 第 2，`Starter Kit` 第 3。
- `关键修复`
  解决了“为什么不是先卖模板”的问题：模板复利更强，但首购动机更弱。
- `保留还是淘汰`
  收敛为 3 个方向。
- `下一轮重点`
  如果继续做第 4 轮，应验证谁最先愿意付首单。
- `是否收敛`
  是。

## 12. 最小验证动作

### 主推方向：`窄场景 Topic Wiki 首包`

- `验证目标`
  判断是否有人愿意为“把现有资料编成可持续提问的主题 wiki”付费。
- `验证对象`
  研究型创作者、独立研究者、AI 从业者中重度资料收集者。
- `验证渠道`
  公众号、X、微信群、知识社群、朋友圈。
- `验证文案/标题`
  `把你过去 3 个月收藏但没用起来的资料，7 天内编成一个可持续追问的 Topic Wiki。不是聊天记录，不是 RAG demo，是你以后还能继续长的知识资产。`
- `报价`
  首批内测价 `999 RMB`
- `交付承诺`
  `<= 30` 份 source，1 个主题，1 个 Obsidian/Codex 可用 wiki，1 次 handoff，1 份风险说明。
- `成功信号`
  72 小时内拿到 3 个以上明确咨询，1 个付费定金，或 5 个以上愿意提供资料试做。
- `失败信号`
  用户只夸概念，不愿意提供自己的真实资料，或只愿意要教程不要结果。

## 13. 小而美 MVP

- `如果不做大产品，现在最值得卖的最小版本是什么`
  `Topic Wiki 首包`
- `它解决的是哪个单点痛点`
  “我有很多资料，但它们并没有变成一个可以持续提问和复用的知识资产。”
- `为什么这个小版本比大版本更值得先做`
  因为它直接卖结果，边界清晰，不需要先做通用平台，也能自然沉淀 schema、模板和案例。
- `它的定价、交付、验证方式`
  `999 RMB`；最多 30 份资料、1 个主题、1 套 wiki；通过公开 demo + 首批内测招募验证。

## 15. 主推方向

### `主推方向`

`窄场景 Topic Wiki 首包`

### `谁会买`

- 重度资料收集但复用效率低的研究型创作者
- 独立研究者
- AI 从业者里的重度 agent 用户

### `为什么现在买`

- 话题刚热，用户刚被教育到“原来知识库可以自维护”。
- 大多数人会卡在落地第一步，不会自己搭、也不信任抽象教程。
- 趁热做一次自己的主题库，有明显炫耀性与实用性。

### `买完得到什么`

- 一个能继续增长的主题 wiki
- 一套自己的 schema
- 一套继续 ingest / query / lint 的操作方式
- 一个带 source trace 的初始结构

### `最快成交路径`

- 先做公开 demo
- 再做限量内测
- 再从首包里沉淀出模板卖给第二批用户

### `怎样沉淀复利资产`

- 行业 schema 模板
- 目录结构模板
- lint 检查清单
- 销售 FAQ
- before/after demo
- 典型行业案例

## 16. 备选方向

- `选题/资料编译订阅`
  适合已经有媒体或内容分发能力的人，做成持续专题底稿。
- `中文 Starter Kit + 模板库`
  适合当第二产品或 upsell，用来接住“不想买服务、想自己搭”的用户。

## 17. 淘汰原因

- `白标 SaaS`
  太重，且已有大量同质化实现开始堆积。
- `反漂移插件作为第一产品`
  真实价值高，但成交语言弱，不如先卖可见成果。
- `纯课程/训练营`
  用户会学，但不一定做；更像知识焦虑产品，不像结果产品。

## 18. 具体操作指南

1. 先做一个公开 demo。
   题材最好选高热但边界清楚的主题，例如 `AI coding agents`、`个人知识库工作流`、`某一垂直行业工具图谱`。
2. 把 demo 交付拆成 6 个可见件。
   `raw/`、`wiki/`、`schema`、`index`、`query demo`、`lint report`。
3. 写一页试卖文案。
   不卖“second brain”，只卖“把你的散资料编成一个可持续提问的主题 wiki”。
4. 限制首单范围。
   `<= 30` 份资料；1 个主题；不接企业全库迁移。
5. 用 3 个问题展示成效。
   `我们知道什么？`
   `哪些地方互相矛盾？`
   `接下来该补什么资料？`
6. 首批用户做完后，再推出 `Starter Kit`。
   用案例带模板，而不是反过来。

## 19. 下一轮验证计划

- 验证 `研究型创作者` 与 `小团队 owner` 哪个群体更快成交。
- 对同一套交付，测试两种销售语言：
  `把散资料变成可问答资产`
  `帮你搭一套 Karpathy LLM Wiki`
- 观察哪种表述转化更高。
- 如果结果产品明显优于概念产品，再决定是否继续做模板库或订阅。
