
请把下面的需求技术文档转成可执行 issue，并设计成适合多个 Codex 子 agent 并行开发的任务计划。

你必须分三步完成：

第一步：拆 issue
- 阅读需求文档和代码仓库。
- 拆成多个最小、独立、可验证的 issue。
- 每个 issue 必须包含：
  - 标题
  - 背景
  - 目标
  - 修改范围
  - 可能涉及的文件
  - 禁止修改的范围
  - 依赖关系
  - 验收标准
  - 测试要求
  - 是否适合并行

第二步：设计并行执行计划
- 输出 DAG：
  - P0：前置任务
  - P1：可并行任务
  - P2：依赖任务
  - Final：集成任务
- 明确哪些 issue 可以同时交给不同子 agent。
- 明确哪些 issue 必须串行。
- 尽量避免多个 agent 修改同一个文件。
- 如果存在共享文件，必须标记冲突风险。

第三步：生成子 agent 执行卡
每个子 agent 执行卡包含：
- Agent ID
- 对应 issue
- 任务目标
- 允许修改的文件
- 禁止修改的文件
- 输入上下文
- 执行步骤
- 测试命令
- 输出格式
- 冲突上报规则

并行开发规则：
1. 每个 agent 只做自己的 issue。
2. 不允许顺手重构无关代码。
3. 不允许修改其他 agent 负责的文件。
4. 发现需要改公共接口时，必须停止并报告。
5. 每个 agent 完成后必须输出 diff 摘要、测试结果和风险点。
6. 最后必须有一个 Integrator 负责合并、消冲突、补测试、生成 PR 描述。

现在开始，不要直接写代码，先输出 issue 拆分和并行执行计划。
