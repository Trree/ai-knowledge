打开 Claude Code，只发了一句你好。然后，1.7 元没了。

第一反应当然是离谱。两个字，凭什么。

但这事真不是按字收费。问题在于，你以为自己在聊天，系统以为自己要开工。

Claude Code 不是一个只会回话的聊天框。它是个工程代理，能读项目，能调工具，能跑命令，能记规则。你敲下你好之前，它往往已经先把一整套启动包背上身了。

那次 `/context` 很能说明问题。`Messages` 只有 8 tokens，整个上下文却差不多 25k。差的那一大截，不是你好，是系统自己带进去的东西。

`system tools` 14k，`skills` 4.4k，`system prompt` 3.6k，`MCP tools` 2.3k。这组数一出来，答案其实已经很清楚了。

你不是在为你好付费。

你是在为启动付费。

`system tools` 是工具说明书，Claude Code 要先知道自己能读什么、改什么、跑什么、调用什么。`system prompt` 是总规则，身份、边界、格式、安全约束，都在里面。

`CLAUDE.md` 和 auto memory，是项目入场资料。文件越长，首轮越重。官方文档里也提到过，auto memory 默认就可能把前 200 行或者 25KB 带进来。`skills` 和 `MCP tools` 也一样，很多时候哪怕只是简介和工具名，也会先占上下文，不是等你真用到了才开始算。

所以第一次最疼，很正常。第一次没有缓存命中。如果你走的是 API 计费，缓存窗口又不长，首轮冷启动基本就是硬吃全额。再加上你如果默认挂的是 Opus，而不是 Sonnet，体感只会更夸张。

还有两个常见坑。一个是 skills 装太多，装的时候图新鲜，结账的时候肉疼。很多根本没用过的第三方 skills，平时看不见，首轮全在收税。

另一个是 `CLAUDE.md` 写太肥。很多人把规范、背景、流程、任务状态全塞进去。写的时候安心，用的时候流血。因为它不是摆设，它会反复参与计费。

所以 agent 时代一个很重要的能力，不是会不会写 prompt，是会不会做上下文架构。会写 prompt 的人很多，会管上下文账单的人，才是真正用明白了 agent 的人。

什么常驻，什么延迟加载，什么放全局，什么放局部。这件事，直接决定你是在开一台轻快的机器，还是拖着一辆满载旧家具的卡车往前跑。

如果你也碰到这种情况，别猜，直接排查。先跑 `/context`，先看账单结构，不要看情绪。重点看 `system tools`、`skills`、`system prompt`、`MCP tools`。如果 `Messages` 很小，总量却很大，问题就不在你说了什么，在系统背了什么。

再看你到底按哪套方式计费。走 API，就看 `/cost`。走订阅，就看 `/status`。先把这个搞清楚，不然连肉疼都疼不明白。

然后做四件事，都是立刻能砍的。

**第一，降模型。** 日常开发先用 Sonnet，真要啃复杂任务再切 Opus。不要让最贵的模型，去处理最便宜的问候。

**第二，清 skills。** 没在用的关掉，很少用的移走，只留真正常用的。

**第三，瘦 `CLAUDE.md`。** 能短就短，能拆到子目录就拆，能局部加载就别全局常驻。

**第四，做一轮 A/B 对比。** 临时关掉 `CLAUDE.md`、auto memory、thinking，再关掉默认的 claude.ai MCP servers，只问一次你好。然后和原版 `/context` 对比。差距一大，问题基本就钉死了。

还有一个细节，很多人会漏。你以为自己走的是订阅，结果本地其实挂着 API key。那账单体验，当然完全不是一回事。

所以这事最值得记住的一句，不是 Claude Code 很贵。而是你得先搞明白，自己到底在为谁付费。

以前用聊天机器人，成本主要跟你说了多少话有关。现在用工程代理，成本越来越跟系统为了开工，提前装进去多少背景资料有关。

你买的不是一句回答。

你买的是待命状态。

所以以后再看到有人说，我就打了个你好，怎么就扣这么多。你可以直接回他。

不是在聊天。

是在开机。

如果你身边也有人刚开始用 Claude Code，把这篇转给他。能省掉的不只是 1.7 元，是之后每一轮对话里悄悄流掉的冤枉钱。
