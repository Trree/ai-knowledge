# 反馈循环是唯一的元模式

## 核心洞察

读完这些材料后发现一件事：表面上在谈 autoresearch、Deep Research、写作方法、产品设计、行为习惯养成——五个完全不同的领域，但它们全部收敛到同一个结构：

> **假设 → 执行 → 测量 → 保留/丢弃 → 新假设**

这不是巧合。这是唯一一种能让知识复利增长的结构。

## 在不同领域的表现

**Autoresearch（ML 研究）**
`program.md` + 自动执行 + 评估指标 + 贪心搜索。Karpathy 的 autoresearch 本质上就是把科研变成了一个 while 循环。关键抽象：可编辑的执行基座 + 稳定的结果协议 + 真反馈驱动的循环。
→ 原始材料：[[sources/autoresearch.md|autoresearch]]、[[sources/Autoresearch 背后的思想提炼.md|思想提炼]]、[[sources/autoresearch 科研版本.md|科研版本]]

**Deep Research + Autoresearch（科学方法）**
Deep Research 只读（综合已有知识），Autoresearch 只写（生成新知识）。单独用都是半个循环。合在一起才是完整的科学方法：读文献 → 形成假设 → 跑实验 → 解读结果 → 读更多文献 → 新假设。
→ 原始材料：[[sources/deepresearch + autoresearch.md|融合分析]]、[[sources/deep-research-report.md|架构报告]]

**写作（Steve Jobs 对话）**
锁定意图 → 写原始判断 → 扩展 → 运行删除循环。评估指标是"压缩记忆率"——读者真正记住了什么。写作不是一次性输出，是反复删减测试的搜索过程。
→ 原始材料：[[sources/steve jobs autoresearch.md|Steve Jobs 论 Autoresearch]]

**行为设计（深度思考习惯）**
B.J. Fogg 的行为设计 + 苏格拉底的提问法，收敛到同一个结论：系统问一个问题 → 用户尝试回答 → 一次追问 → 撤退。最好的行为干预是"点燃后退出"。
→ 原始材料：[[sources/养成深度思考的习惯.md|圆桌原版]]

**产品设计（Topic Wiki）**
不做平台，做一次编译交付：收集材料 → 编译 wiki → 交付 → 让用户决定是否继续。MVP 的本质是一个有限循环，不是无限循环。
→ 原始材料：[[Topic Wiki mvp|Pipeline MVP]]、[[Topic Wiki  prd|PRD]]

## 为什么这个模式重要

因为它暗示了一个统一的世界观：**任何值得做的事情，都可以被重新设计为一个反馈循环**。不是一次性交付，而是持续迭代。不是一个答案，而是一个越来越好的搜索过程。

这也是 Karpathy LLM Wiki 的真正精神——不是"用 LLM 生成摘要页面"，而是"让知识在循环中复利增长"。
