为什么只说一句「你好」，Claude Code 也会先扣 1.7 元

如果你在 Claude Code 里只发了一句「你好」，账单却先走了 1.7 元，先不用急着判断它乱收费。更常见的情况是，你付的不是这两个字的费用，而是 Claude Code 为了进入工作状态，先加载了一整包上下文。

把话说得更直一点，很多时候，这笔钱不是「回复费」，而是「启动费」。

截至 2026 年 4 月 23 日，Anthropic 官方文档对这件事的说明已经比较清楚了。Claude Code 在你真正开始对话前，就可能先把 `CLAUDE.md`、auto memory、MCP tool names、skill descriptions 加进上下文。Claude API 的工具调用计费，也会把 `tools` 参数和工具使用的系统提示一起算进去。

这就是为什么，你明明只说了一句很短的话，账单看起来却不像只为这句话买单。

如果你手里已经有一次 `/context` 数据，先看两个地方。

第一，看 `Messages` 占多少。

第二，看 `system tools`、`system prompt`、`skills`、`MCP tools` 占多少。

如果 `Messages` 很小，总量却很大，那问题通常就不在你说了什么，而在系统为了让 Claude Code 进入工作状态，先背了多少东西。

比如一种很典型的情况是，`Messages` 只有几个 tokens，但整个上下文已经到了 25k 左右。那这笔钱的大头，显然不是聊天内容本身，而是启动时自动装载的系统层和工具层。

这里最容易被忽略的，有四块。

`system tools`，可以把它理解成工具说明书。Claude Code 要先知道自己能读什么、改什么、跑什么命令、怎么调工具。

`system prompt`，可以把它理解成总规则。模型是谁、边界在哪、输出要注意什么，这些都在里面。

`CLAUDE.md` 和 auto memory，更像项目入场资料。官方文档写得很明确，这两类内容会在每个会话开始时加载，其中 auto memory 默认会带入前 200 行或 25KB。

`skills` 和 `MCP tools`，哪怕只是名字、简介、基础定义，也会占上下文，不是等你真正调用了才从零开始算。

第一次尤其容易贵，也不奇怪。

因为第一次通常没有缓存命中。官方定价文档也写了，prompt caching 要在后续请求里复用，首轮冷启动本来就更容易吃到完整成本。

还有三个因素，会把这种体感继续放大。

一个是模型选得太重。

截至 2026 年 4 月 23 日，Anthropic 官方价格里，Claude Opus 4.6 的基础输入价格是 `$5 / MTok`，Claude Sonnet 4.6 是 `$3 / MTok`。如果你只是做日常开发、环境测试或者简单问答，却把最贵那档模型常驻开着，账单自然更刺眼。

一个是 skills 装得太多。

skills 在启动时先加载描述，不是全文。但如果你装了很多平时根本不用的 skills，这些描述叠起来，也会变成一层稳定的固定成本。

一个是 `CLAUDE.md` 写得太肥。

官方建议每个 `CLAUDE.md` 控制在 200 行以内。因为它不是摆设，它会在每次会话启动时进入上下文。写得越长，首轮越重。

那遇到这种情况，最实用的处理办法是什么。

不是继续猜。

是按顺序排查。

第一步，跑 `/context`。

先把账拆开看，不要只盯着总金额。你需要知道，大头是在 `Messages`，还是在 `system tools`、`skills`、`system prompt`、`MCP tools`。

第二步，确认你到底在按哪种方式计费。

如果你走的是 API，去看 `/cost`。如果你走的是订阅，去看 `/status`。另外还要顺手检查一下本地是不是设置了 `ANTHROPIC_API_KEY`。官方文档明确说了，这个变量一旦生效，会优先走 API key，而不是你的 Pro、Max、Team 或 Enterprise 订阅。

第三步，把默认模型调到更合适的档位。

不是所有任务都需要 Opus。日常开发和普通排查，先用 Sonnet 往往更合理。真的遇到复杂架构、难题推理，再切更贵的模型。

第四步，清一遍 skills 和 `CLAUDE.md`。

不常用的 skills 先关掉。只在局部目录才有用的规则，尽量放回局部，不要全局常驻。`CLAUDE.md` 里只留每次会话都必须知道的事实和规则，不要把半个项目说明书都塞进去。

第五步，如果你想确认问题是不是出在启动包，可以做一次简单对照。

临时关闭 `CLAUDE.md`、auto memory 和 claude.ai MCP servers，再发一次同样的话，对比前后 `/context`。官方文档里有对应的环境变量，比如 `CLAUDE_CODE_DISABLE_CLAUDE_MDS=1`、`CLAUDE_CODE_DISABLE_AUTO_MEMORY=1`、`ENABLE_CLAUDEAI_MCP_SERVERS=false`。如果前后差距很大，问题基本就定位了。

说到底，这件事真正提醒我们的，不是 Claude Code 很贵，而是 agent 工具的成本结构已经和聊天机器人不一样了。

以前你主要是在为「说了多少话」付费。

现在你越来越是在为「系统为了开工，先装进去多少背景资料」付费。

所以，下一次再看到一句「你好」就先扣钱，不用先判断自己是不是被坑了。先跑 `/context`，先看结构，再决定要不要骂。

很多时候，真正该优化的，不是那句「你好」。

是你让 Claude Code 在开口前，先背了多少东西。
