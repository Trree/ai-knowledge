## 工具介绍

名称：Skill Workflow 编排系统  
核心功能：将多个 AI skill 组合成可复用 workflow，支持 DAG 依赖编排、状态持久化、断点恢复、步骤替换、A/B 对比、人工 gate 控制  
应用场景：快速组合编排开源SKILLS、流程自动化、A/B Skills对比, 团队 SOP 固化

## 适用场景

|   |   |   |   |
|---|---|---|---|
|场景|适用度|优势|劣势|
|快速编排开源和内部SKILLS|⭐⭐⭐⭐⭐|快速将开源优秀的SKILL固化为统一流程|示例 workflow 仍需替换为真实开发 skill|

## 最佳实践

做这些事

1. 先把高频任务抽象成固定步骤
- - 先找重复任务，不要一上来编排所有事
    - 明确每一步输入、输出和完成标准
        
1. 让 skill 尽量原子化
- - 一个 skill 只解决一类问题
    - 不要把多个不相关动作硬塞进一个 skill
1. 保留运行记录
- - 每次运行都保存状态和中间产物
    - 失败时优先复盘记录，而不是凭感觉改
1. 把人工 gate 放在关键点
- - 方向分叉前确认
        
    - 对外发布、提交、推送这类不可逆动作前确认
        

1. 用 A/B compare 优化单步骤
    

- - 在同一输入下替换一个 skill 做对比
        
    - 优化应该基于结果，而不是主观偏好
        

1. 改 workflow，不要只改单次输出
    

- - 单次手修只能救这一轮
        
    - 调整 workflow 才能让后续所有运行受益
        

避免这些事

1. 在每个步骤都插人工检查点
    

- - 会严重打断上下文
        
    - 人会从设计者退化成点按钮的审核员
        

1. 把 workflow 当成单个 prompt 的放大版
    

- - 如果步骤边界不清晰，流程会很快失控
        
    - 编排不是把 prompt 叠起来，而是设计协作关系
        

1. 每次问题都直接手工改结果
    

- - 看起来快，长期最慢
        
    - 相同问题下次还会重复出现
        

1. 用不同输入做 A/B 对比
    

- - 对比结论会失真
        
    - 无法真正判断是 skill 差异还是输入差异
        

1. 还没形成稳定任务就过度工程化
    

- - 低频任务先人工摸清楚流程
        
    - 高频稳定后再沉淀为 workflow
        

## 结论

Skill Workflow 编排系统最适合解决的，不是单个问题的回答质量，而是整类重复性复杂任务的执行稳定性。

它的价值主要体现在三件事上：

- 把流程显式化，从经验操作变成结构化定义
    
- 把执行可追溯化，失败后能恢复、能复盘、能定位问题
    
- 把优化方式系统化，从手改输出转向迭代 workflow
    

从团队角度看，这个项目不是单纯的 AI 工具集成，而是在尝试把人和 AI 的协作流程做成一套可运行、可验证、可持续优化的工程系统。

如果继续推进，最值得优先落地的方向有两个：

- 选一个高频、标准化程度高的业务流先跑通
    
- 围绕真实运行记录建立优化闭环，而不是停留在定义层
